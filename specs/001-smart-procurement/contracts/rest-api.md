# Contract — Frontend ↔ Backend REST API

- **Transport**: REST/JSON over HTTPS. **Spec**: OpenAPI 3.1 auto-generated by FastAPI at
  `/openapi.json`; the frontend generates TypeScript types + RTK Query endpoints from it.
- **Auth**: `Authorization: Bearer <access_jwt>`. `POST /auth/login` → `{access, refresh}`;
  `POST /auth/refresh`; `POST /auth/logout` (revokes refresh token).
- **AuthZ**: every route declares a required permission; the backend enforces it (FR-066).
  403 = authenticated but lacks permission; 401 = missing/expired token.
- **Versioning**: path prefix `/api/v1`.
- **Pagination**: list endpoints take `?limit=&cursor=`; return `{items, next_cursor}`.
- **Correlation**: every response carries `X-Correlation-Id`; clients may send one.

## Unified error model

```json
{ "error": {
    "code": "string_snake_case",        // e.g. policy_author_equals_approver
    "message": "human readable",
    "details": { "field": "reason" },    // optional
    "correlation_id": "uuid"
} }
```

HTTP status: 400 validation, 401 auth, 403 permission, 404, 409 state conflict
(e.g. approving a non-`pending_approval` policy), 422 domain rule violation, 502/504
external-integration failure (mapped from adapter/connector errors), 500 unexpected.

## Guarantees encoded in this contract

- No endpoint executes a procurement action directly; approval/policy paths **enqueue** a
  job that calls `LormEnforcementService` then `execution.dispatch()` (FR-069).
- `/policies/*/approve` and `/promotion-requests/*/approve` return `409` on
  separation-of-duties violation regardless of the caller's roles (FR-038/FR-065).
- Secret material is write-only: it is accepted in `credential` request bodies and never
  appears in any response (FR-068).
- All list/detail responses for risks, recommendations, actions and audit include the
  evidence/`data_used` references needed for explainability (FR-061/FR-070).
